# La web y la API se sirven desde el mismo origen

El navegador pide `/api/*` al origen de la web y Next lo reescribe hacia la API (`rewrites` en `apps/web/next.config.mjs`, con destino `API_INTERNAL_URL` o `localhost:4000` en desarrollo); el cliente oRPC usa `window.location.origin` como base, y en SSR `getServerSideProps` llama directamente a `API_INTERNAL_URL` reenviando la cookie (`integrations/auth/server.ts`). Se elige así para que la cookie de sesión sea del mismo sitio (`httpOnly`, `sameSite: 'lax'`, `auth.cookies.ts`) y la API no necesite CORS (`main.ts` no llama a `enableCors`). Si la web llamara a la API en otro origen, la sesión dejaría de viajar y haría falta CORS con credenciales.
